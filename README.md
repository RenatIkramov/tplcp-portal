# 3PL Customer Portal

B2B self-service портал 3PL-оператора. Бэкенд на Spring Boot + PostgreSQL,
фронтенд — обычные HTML, CSS и JavaScript без сборки, работающие с API портала.

## Где что лежит

| Путь                                  | Что это                                              |
|---------------------------------------|------------------------------------------------------|
| `src/main/java/com/ahlers/portal3pl/` | код приложения                                       |
| `src/main/resources/application.yml`  | подключение к базе, Flyway — свой у каждой машины, в git не идёт |
| `src/main/resources/application-prod.yml` | рабочий портал (профиль `prod`), без паролей     |
| `src/main/resources/db/migration/`    | миграции базы (Flyway), V1…V134                      |
| `src/main/resources/static/`          | фронтенд: `index.html`, `css/`, `js/`                |
| `src/main/types/portal.d.ts`          | типы для проверки JavaScript (`tsc`, `tsconfig.json`) |
| `src/test/java/com/ahlers/portal3pl/` | тесты, в том числе браузерные (`browser/`)           |
| `tools/`                              | инструменты и демо-данные, см. `tools/README.md`     |

Пакеты приложения:

| Пакет       | Назначение                                                     |
|-------------|----------------------------------------------------------------|
| `config`    | контекст запроса, изоляция данных, текущий пользователь, защита запросов, коды ошибок |

| `admin`     | пользователи, доступы, справочники уровня портала              |
| `audit`     | журнал действий и история карточек                            |

| `catalog`   | номенклатура, контрагенты, биллинг                             |
| `lists`     | списки с отбором и страницами на сервере                      |
| `columns`   | справочник колонок: выбор, порядок, переименование под клиента |
| `i18n`      | языки и тексты интерфейса                                      |
| `excel`     | шаблоны и загрузка из Excel                                    |
| `common`    | имена колонок, приведение типов, тексты отказов                |

### Фронтенд

Обычные файлы, которые правятся руками. Сборки нет.

| Путь                         | Что это                                         |
|------------------------------|-------------------------------------------------|
| `static/index.html`          | разметка всех экранов                           |
| `static/css/portal.css`      | оформление                                      |
| `static/js/portal/*.js`      | код портала, по файлу на раздел; общее — `core.js` (`PORTAL.api`, `PORTAL.esc`, `PORTAL.call`) |
| `static/js/demo/reports.js`  | последний кусок демо — каталог отчётов, уйдёт вместе с ним |
| `static/js/i18n-fallback.js` | `T()` и запасные русские подписи               |

`i18n-fallback.js` собирается из базы инструментом
`tools/gen_i18n_fallback.py` — руками его не правят. Настоящие тексты
страница забирает с сервера до первой отрисовки; словарь в файле —
страховка на случай, когда портал не ответил.

Скрипты подключены обычными `<script src>`, не модулями. Порядок
подключения в `index.html` важен: `core.js` — первым, остальные
пользуются тем, что он объявил в `PORTAL`.

Данные клиента в разметку как скрипт не подставляются: щелчки идут
через `data-call` / `data-args` (`PORTAL.call`), тексты — через
`PORTAL.esc` и белый список разметки `PORTAL.safeHtml`.

## Запуск

1. PostgreSQL 16 или новее, база `tplcp`, в ней схема `dbo`.
2. JDK 21 или новее: *File → Project Structure → SDK*.
3. *File → Open* → папка с `pom.xml`, дождаться загрузки зависимостей.
4. Открыть `PortalApplication.java`, нажать зелёный треугольник.
5. Открыть `http://localhost:8080/`.

Миграции накатывает **Flyway при старте приложения** — руками ничего
накатывать не нужно. Подключается он владельцем схемы `portal_owner`,
приложение работает ролью `portal_app`; и пользователи, и пароли заданы
в `application.yml` (`spring.flyway.user` и `spring.datasource.username`).

**Владелец схемы — `portal_owner`, не суперпользователь** (`V132`).
Роль создаёт сама миграция, но без входа: пароль в git не кладётся.
На новой базе первый запуск идёт под `postgres` (он накатит всё по
`V132` включительно), затем один раз под `postgres`:

```sql
ALTER ROLE portal_owner LOGIN PASSWORD '…';
```

и в `application.yml` — `spring.flyway.user: portal_owner` с этим
паролем. Если следующую миграцию накатит кто-то другой, упадёт
`DatabaseRolesTest`.

**На чистой базе** после миграций есть одна учётная запись — `admin`
с первым паролем из `V18`; портал при входе попросит сменить его.
Демо-данные — `tools/dev-data.sql`, накатить один раз вручную,
см. `tools/README.md`. Это не миграция нарочно: такие данные нужны
только на машине разработчика.

### Рабочий портал

Запуск с профилем `prod`: `--spring.profiles.active=prod`. Пароли —
только из переменных окружения, в файлах их нет:

| Переменная | Что это |
|---|---|
| `SPRING_DATASOURCE_URL`, `SPRING_DATASOURCE_USERNAME`, `SPRING_DATASOURCE_PASSWORD` | база и роль `portal_app` |
| `SPRING_FLYWAY_USER`, `SPRING_FLYWAY_PASSWORD` | владелец схемы `portal_owner` — для миграций при старте |
| `PORTAL_ADMIN_INITIAL_PASSWORD` | первый пароль `admin`, не короче 12 знаков; нужен только на первом запуске |

- Пока у `admin` пароль из `V18`, портал с профилем `prod` не
  запустится без `PORTAL_ADMIN_INITIAL_PASSWORD` (`DefaultPasswordGuard`).
- Пароль роли `portal_app` из `V12__rls.sql` (`portal_app_dev`) на
  рабочем сервере сменить при установке: `ALTER ROLE portal_app PASSWORD '…'`.
- Портал рассчитан на обратный прокси с HTTPS: адрес и схему он берёт
  из `X-Forwarded-*`, кука сеанса — только по HTTPS. Защитные заголовки
  ставит сам (`SecurityHeadersFilter`).
- Сеансы хранятся в памяти: перезапуск просит всех войти заново,
  второй экземпляр портала пока невозможен.

## Проверки

```
mvn clean test                          все
mvn test -DexcludedGroups=browser       без браузерных
```

Проверки работают против **локальной базы** и убирают за собой
созданные строки. Учётки и доступы они готовят владельцем схемы
(`OwnerDb`, учётные данные — из `spring.flyway.*`): портал туда
напрямую не пишет. Около сотни из них — браузерные: Spring поднимает
портал на свободном порту, Playwright открывает его настоящим Chromium
и смотрит, что отрисовалось и что ушло на сервер. Первый запуск
скачивает Chromium (~130 МБ); без сети браузерные помечаются
пропущенными, а не падают — см. `BrowserTestBase`.

Проверка JavaScript: `tsc -p .` в корне проекта (типы —
`src/main/types/portal.d.ts`).

Подробности — документ «Браузерные проверки» в проекте на claude.ai.

## Вещи, которые важно понимать в этом коде

**В SQL нет фильтра по поклажедателю.** Его накладывает база политикой
RLS. Сделано специально: один забытый `WHERE` в одном отчёте перестаёт
быть утечкой данных между клиентами оператора (§5 ТЗ). Ссылки документа
на товар, поставщика, грузополучателя сверяет с клиентом документа
триггер (`V128`).

**Подключаемся ролью `portal_app`, а не владельцем схемы.** Владелец
обходит политики RLS, и изоляция молча перестала бы работать. Отсюда
же правило проверки: SQL, проверенный под `postgres`, не проверен
вовсе — под ним политики не участвуют, а `DELETE` без выставленного
контекста удаляет ноль строк **без ошибки**.

**Учётки, доступы и токены `portal_app` только читает** (`V133`), хэш
пароля не видит вовсе. Меняют их функции владельца (`auth_*`,
`admin_*`). Чтение `app_user` выдано по колонкам: новой колонке нужен
`GRANT SELECT (колонка) ON app_user TO portal_app` в той же миграции.

**Новая таблица у `portal_app` — только на чтение** (`V134`). Если
портал должен в неё писать, миграция выдаёт это явно:
`GRANT INSERT, UPDATE, DELETE ON таблица TO portal_app`. Функции dbo
вызывает только `portal_app` (не `PUBLIC`); у функций `SECURITY DEFINER`
— `SET search_path = dbo, pg_temp`, проверяет `DatabaseRolesTest`.

**`set_config` вызывается внутри транзакции.** Приложение работает
через пул соединений: вне транзакции нет гарантии, что запрос уйдёт
в то же соединение. Первая строка любого нового метода чтения —
`depositorScope.apply()`. Язык и `app.actor` (кто действует — для
журнала) ставит сам пул, `LocaleDataSource`, при каждой выдаче соединения.

**Сеанс сверяется с базой на каждый запрос.** Блокировка, смена роли,
пароля или отзыв поклажедателя гасят открытые сеансы (`V121`).

**Отправка в WMS — через очередь** (`wms_outbox`, `WmsOutbox`, `V127`).
«Подтвердить» ставит «Отправляется» и кладёт задание; WMS вызывается
вне транзакции базы, неудачу портал повторяет раз в минуту, после 15-й —
«Ошибка отправки» и кнопка «Отправить ещё раз».

**Одновременная правка черновика.** Карточка отдаёт `version`, экран
шлёт её в `If-Match`, устаревшая запись получает 409 (`EditVersion`).

**Применённую миграцию не правят никогда.** Flyway держит контрольную
сумму, и правка накатанного файла ломает проверку у всех, кто базу
уже обновил. Любое дополнение — новая версия, и начинается она с
`SET search_path = dbo;`. Следствие, которое смущает при первом чтении:
анализатор IDE показывает в старых миграциях «не найдена колонка». Так
и должно быть — миграция описывает схему своего дня, а не сегодняшнюю.

## Решения, принятые по ходу

Подробности — в документах проекта на claude.ai.

- **Р1.** Одна строка документа может относиться к нескольким партиям.
  Плановое количество хранится один раз (запись без партии), фактическое —
  на записях с партиями; состав документа агрегирует, детализация
  разворачивает.
- **Р2.** ~~Два юрлица оператора на одном экземпляре портала~~ —
  **отменено заказчиком.** Счета и акты приходят через интеграцию
  готовыми, значит реквизиты юрлица порталу не нужны.
- **Р3.** React не будет, сборщика фронтенда нет — см. выше.
- **Р4.** Регистры и справочники, ведущиеся в WMS, — кэш, а не источник
  истины. Превышение доступного количества предупреждает, но не
  запрещает: последнее слово за WMS.
- **Р5.** Документ принадлежит порталу, пока он черновик. После
  подтверждения владелец — WMS: статусы приходят оттуда, портал документ
  не редактирует.
- **Р6.** Номер документа — `[тип][YYMMDD][счётчик]`, например
  `O261014001`. Счётчик на тип и день, один на всех поклажедателей.
- **Р7.** Документ появляется в базе по кнопке «Сохранить», а не при
  открытии карточки.
